# gbc-to-md

[![Host CI](https://github.com/celsowm/gbc-to-md/actions/workflows/ci.yml/badge.svg)](https://github.com/celsowm/gbc-to-md/actions/workflows/ci.yml)
[![SGDK build](https://github.com/celsowm/gbc-to-md/actions/workflows/sgdk.yml/badge.svg)](https://github.com/celsowm/gbc-to-md/actions/workflows/sgdk.yml)

Experimental static-recompilation backend for running Game Boy / Game Boy Color code generated by [`gbrecomp`](https://github.com/arcanite24/gb-recompiled) on the Sega Mega Drive / Genesis with [SGDK](https://github.com/Stephane-D/SGDK).

> **Status:** research prototype. The host-side compatibility suite is substantial, but this project does not claim general GB/GBC compatibility yet. Compatibility must be demonstrated feature by feature and, eventually, game by game.

## What this project is

The design keeps Game Boy CPU behavior in statically recompiled C and replaces desktop-oriented runtime pieces with a compact Mega Drive target:

```text
Game Boy / Game Boy Color ROM
            |
            v
        gbrecomp
            |
            v
    generated native C
            |
            v
   compact GBRT-SGDK runtime
            |
      +-----+------+----------------+
      |            |                |
      v            v                v
 Mega Drive VDP   JOY       SRAM / SEGA mapper
```

It is deliberately **not** a traditional full-framebuffer emulator. Tiles, tilemaps, sprites, scrolling, input, interrupts, timers, cartridge RAM, and ROM banking are translated into Mega Drive/SGDK primitives.

## Current capabilities

The automated synthetic fixtures currently cover:

- real C emitted by GB Recompiled `v0.1.0`;
- Game Boy 2bpp tile conversion to Mega Drive 4bpp tiles;
- background map updates with dense-row batching;
- OAM to Mega Drive sprite translation;
- D-pad/button input through SGDK JOY state;
- horizontal and vertical scrolling;
- VBlank IRQ, `HALT`, interrupt dispatch, and `RETI`;
- Timer IRQ with `DIV`, `TIMA`, `TMA`, and `TAC` frame-time progression;
- collision and dynamic tilemap mutation in an IRQ-driven mini-game fixture;
- MBC1 and MBC1M ROM/RAM banking;
- MBC3 ROM/RAM banking plus the tested RTC/latch subset;
- MBC5 9-bit ROM banking across 512 banks;
- guest ERAM backed by Mega Drive cartridge SRAM;
- retained ROM reads above 4 MiB through the official SEGA 512 KiB mapper model;
- host-side equivalence checks against the upstream GBRT runtime for the mapper/timing fixtures.

See [`docs/COMPATIBILITY.md`](docs/COMPATIBILITY.md) for exact boundaries.

## Quick start: host verification

### Ubuntu / Debian

```bash
sudo apt-get update
sudo apt-get install -y \
  build-essential binutils curl git python3 ca-certificates \
  openjdk-17-jre-headless

make doctor
make bootstrap
make test
```

`make bootstrap` downloads the pinned GB Recompiled release into `.deps/` and verifies its SHA-256 checksum. No third-party executable is committed to this repository.

Run the full host compatibility suite with:

```bash
make verify-ci
```

The larger source-size report can be included with:

```bash
make verify
```

## Build a Mega Drive ROM

Install the pinned SGDK and Linux m68k cross-toolchain:

```bash
make bootstrap-sgdk
```

Build the IRQ-driven `cakegame` fixture:

```bash
make sgdk
```

Expected artifact:

```text
build/artifacts/cakegame/rom.bin
```

For the 8 MiB MBC5/far-ROM stress fixture:

```bash
make sgdk-mbc5
```

This enables SGDK's official SEGA bank-switch configuration in the local ignored SGDK checkout and builds:

```text
build/artifacts/mbc5test/rom.bin
```

See [`docs/BUILDING.md`](docs/BUILDING.md) for manual toolchain paths, environment variables, mapper constraints, and post-link checks.

## Design highlights

### Host VBlank instead of software LCD traversal

For conventional frame-driven software, the Mega Drive VDP becomes the host frame clock. The runtime can avoid spending host CPU time traversing every Game Boy LCD scanline while still exposing VBlank behavior to generated code.

The synthetic polling fixture structurally collapses from roughly 70,224 guest cycles / 8,700+ tick calls per frame to hundreds of guest cycles / tens of tick calls per host frame. The IRQ-driven path is smaller still. These are structural host measurements, **not** a claim that every commercial game will fit a 7.67 MHz 68000 budget.

### Guest banking is not Mega Drive physical banking

MBC1/MBC3/MBC5 select Game Boy guest banks. Recompiled code in those banks is already native C and usually needs no physical ROM remap. The SEGA mapper is only required when generated/native code reads retained raw ROM bytes located outside the directly visible cartridge window.

### Cartridge SRAM keeps WRAM pressure low

A 32 KiB guest ERAM array would consume roughly half of the Mega Drive's 64 KiB work RAM. The target can instead route guest ERAM through SGDK cartridge SRAM accessors, keeping the target context/backend footprint around the high-teen KiB range in the current host-size proxy.

## Synthetic fixtures only

This repository does not include commercial ROMs or copyrighted game assets. All test `.gb` files are generated locally from original Python fixture generators and are excluded from Git.

Users are responsible for supplying any legally obtained ROM used for private compatibility research.

# Testing strategy

## Philosophy

Compatibility work is driven by deterministic synthetic fixtures rather than ad-hoc game-specific patches. Each fixture isolates a hardware behavior and compares the compact runtime against either direct expectations, upstream GBRT, or both.

Generated files are disposable and live under `build/generated/`.

## Fixture matrix

| Fixture | Purpose |
|---|---|
| `basicdemo` | Basic tiles, map, sprite, input, scrolling, LY/VBlank polling path |
| `irqtest` | VBlank IRQ, `IE/IF`, `EI`, `HALT`, ISR dispatch, `RETI` |
| `timertest` | Timer progression and Timer IRQ while guest CPU is halted |
| `cakegame` | IRQ-driven mini-game: input, movement, collision, animation, map mutation |
| `mbc1test` | MBC1 ROM/RAM banking and banked native dispatch |
| `mbc3test` | 2 MiB / 128-bank MBC3 stress, ERAM, RTC/latch subset |
| `mbc5test` | 8 MiB / 512-bank MBC5 stress, 9-bit bank selection, far retained-ROM reads |

The fixture ROMs are generated by `fixtures/make_*.py` and are ignored by Git.

## Core smoke

```bash
make test
```

This covers:

- backend tile/input/OAM/map behavior;
- tiny ROM instruction smoke execution;
- real generated C on the compact runtime;
- host-VBlank performance smoke.

## Upstream equivalence

```bash
make upstream-test
make irq-test
make timer-test
make cake-test
make mbc1-test
make mbc3-test
make mbc5-test
```

The mapper/timing scripts generate the same synthetic ROM for both the embedded upstream runtime snapshot emitted by `gbrecomp` and the compact SGDK runtime. They assert equivalent guest-visible completion state for the behavior under test.

## SGDK syntax gates

```bash
make syntax-test
```

The test suite provides minimal SGDK stubs so target-facing C code can be compiled by the host compiler with strict warnings. This catches API/signature/preprocessor regressions without pretending that a host compile is equivalent to a real m68k link.

## Full CI target

```bash
make verify-ci
```

This is the expected pre-commit broad verification target.

## Mapper/source-size report

```bash
make mapper-size
```

This intentionally regenerates the mapper fixtures and reports:

- guest ROM bytes;
- generated core C bytes;
- generated `rom.c` bytes;
- an x86 `-Os` `.text` proxy for generated code.

The report is diagnostic, not a Mega Drive ROM-size measurement.

## Real SGDK cross-build

```bash
make sgdk
make sgdk-mbc5
```

A successful cross-build gives stronger evidence because it exercises the actual SGDK linker script, m68k compiler, raw `.incbin` ROM blob, target SRAM definitions, and far-ROM post-link placement checks.

## Adding a new fixture

A new hardware feature should normally add:

1. a deterministic generator under `fixtures/`;
2. explicit completion/result bytes in guest WRAM or another inspectable state;
3. a headless upstream test when upstream GBRT supports the behavior;
4. a compact-runtime test;
5. target syntax coverage when SGDK-specific APIs are involved;
6. documentation updates in `docs/COMPATIBILITY.md`.

Do not add a commercial ROM as a regression fixture.
